## 1. Security posture

### 1.1 Verdict

| Question | Verdict | Evidence |
| --- | --- | --- |
| Does the shipped client know backend server names or IPs? | **No.** | Test `shipped client files contain no lab IPs, internal hostnames, or extra origins` over `CLIENT_SHIPPED`. |
| Can the browser reach a chain node or vendor RPC from the UA? | **No.** | CSP `connect-src 'self' https://tkrwallet.scratchpost.ai`; `host_permissions` deep-equals that origin; `ui.js` has no `fetch`. |
| Are keys ever sent to the edge? | **No.** | Vault is local AES-GCM. Balance GETs send the public address. Swap/build returns **unsigned** tx; `broadcastRaw` sends raw bytes after local sign. |
| Does the CLI print secrets? | **No.** | `runCliCommand` refuses `seed`/`mnemonic`/`phrase`/`secret`/`private`/`privkey`/`password`/`passwd`/`export`/`backup`. Status prints `shortAddress` only. |
| Is the live GitHub runner in git? | **No (must stay that way).** | `actions-runner/.credentials` is OAuth material on disk. `.gitignore` now lists `actions-runner/` and `.rdapq/`. |

**Overall:** strong single-origin self-custody client. Residual: XSS ⇒
in-memory phrase (CSP + no `innerHTML` are load-bearing); operator scripts
and deploy docs still name ATHENA/Vault (not executed by the PWA); production
nginx/LAN faces live in another repo.

### 1.2 Custody (asserted)

- PBKDF2-SHA256 **600000** iterations → AES-GCM (`crypto.js` `KDF_ITERATIONS`).
- Canonical BIP-39 vector `abandon … about` →
  `0x9858EfFD232B4033E47d90003D41EC34EcaEda94`.
- Wrong password fails closed.
- Phrase is not in IndexedDB or the viewing-session blob.
- Auto-lock cannot be off; max 60 minutes.
- Create path: phrase shown once, typed confirm, wipe.

### 1.3 Web / extension

- `index.html` CSP: `default-src 'none'; script-src 'self'; connect-src 'self' https://tkrwallet.scratchpost.ai; media-src 'self' blob:` (camera).
- MV3 `extension_pages` CSP mirrors connect/img/media; `script-src 'self'`.
- No inline `<script>` (MV3 cannot relax it).
- SW: network-first, `/api/` never cached, same-origin GET only, cache
  `tkrwallet-v15`.
- Extension ID pinned via `key` in `manifest.json`. CRX private PEM is
  gitignored; checkout script shreds tmpfs.

### 1.4 Dirt that must never be committed

| Path | Why |
| --- | --- |
| `actions-runner/.credentials` | Live runner OAuth. Staging this directory is an incident. |
| `.rdapq/` | Local RDAP-Q session state. |
| `key.pem` / `*.crx` / vault JSON outfiles | Secrets. Operator scripts write mode 600 under `$HOME/.config`. |

### 1.5 Honest camera errors (0.10.17)

The previous popup path told the user “Camera permission was denied. Nothing
was signed.” A camera failure is not a signing event. `sendCameraErrorText`
maps `NotAllowedError` / `NotFoundError` / `NotReadableError` without that
lie. Toolbar popup and side panel bounce to a tab because Chrome will not
prompt `getUserMedia` there.

## 2. AI ↔ Human parity

The human surface is the GUI. The AI surface in this repo is the in-wallet
CLI (`runCliCommand`), which shares the unlocked session and the same
`wallet.js` / `crypto.js` contract. There is **no** separate MCP server or
headless agent API in tkrWallet.

Both sides are supposed to be the same wallet: same origin, same vault, same
“nothing is signed unless the user (or a CLI action that is implemented)
asks.” They are **not** feature-equal.

| Human UI | CLI verb | Shared backend | Parity |
| --- | --- | --- | --- |
| Terminal open | (overlay) | — | yes |
| `help` | `help`, `?` | — | yes |
| lock state / short address | `status` | viewing session / RAM | yes (CLI never prints the full address or keys) |
| Home | `home` | `go` | navigation only |
| Swap screen | `swap` | `go` | **navigation only** — CLI cannot Quote or Swap Now |
| Activity | `activity` | `go` | yes (placeholder for both) |
| Search | `search`, `search <q>` | `searchTokens` / catalogue | opens search; does not itself fetch |
| Settings | `settings` | `go` | navigation only |
| Lock now | `lock` | `lockNow` | yes |
| Dock | `dock` | `chrome.sidePanel.open` | yes |
| Close terminal | `close`, `exit` | — | yes |
| Clear log | `clear` | — | yes |
| Send / contacts / QR | — | store + camera | **gap** |
| Receive QR | — | `paintReceiveQr` | **gap** |
| Quote / Swap Now | — | `quoteSwap` / `buildSwap` / `broadcastRaw` | **gap** (human only) |
| Buy Now → swap pair | — | `openSwapFor` | **gap** |
| Unlock / import / create | — | `crypto.js` + `store.js` | **gap** (and correctly so for secrets) |
| Connect / Disconnect | — | nonce / session / logout | **gap** |
| Add token / extra account / FX / currency | — | `wallet.js` + settings | **gap** |
| Token detail | — | `goToken` | **gap** |
| Pending IcePike sign | — | `listPendingSigns` + local sign | **gap** |
| `seed` / `export` / `password` | refused | — | **intentional non-parity**: CLI must not print secrets |

**Named gaps, not implied equality.** An agent with only the CLI can
navigate, lock, dock, and read a truncated public status. It cannot quote,
swap, send, connect, or unlock. Unlock/create staying out of the CLI is a
security choice (the refuse list). Quote/send staying out is unfinished
parity, not a documented command that is broken.

Human and AI still share the **contract**: `wallet.js` is the only network
caller; `crypto.js` is the only key handler; CSP still applies when the CLI
runs inside the page.

## 4. Swap functionality (driven)

### 4.1 Data layer

`wallet.quoteSwap(payload, fetchFn)` and `wallet.buildSwap(payload, fetchFn)`
are the real shipped functions. The suite injects `fetchFn` and records
URL/method/body.

Observed:

- Quote is `POST` to a URL containing `/api/wallet/swap/quote`,
  `credentials: "include"`, JSON body equal to the payload
  `{ chain_id, input_mint, output_mint, amount }`.
- A 200 JSON body is returned as-is (`ok: true`, `out_amount`, `quote`).
- Build is `POST` `/api/wallet/swap/build` with `{ chain_id, quote }`.
- A non-OK response becomes `{ ok: false, error: "quote-expired" }` from the
  body’s `error` field — not a thrown empty failure.

Test: `quoteSwap and buildSwap POST the real edge paths and return the quote body`.

### 4.2 UI / expiry (already in the suite)

- Swap screen is not “Under construction”.
- Chains in the pair list: `[1, 8453, 4663, 900001, 728126428]`.
- `startQuoteTimer(); openQuoteDialog();` after a live quote.
- `quoteStillLive()` gates Swap Now (`disabled` + `aria-disabled` when stale).
- Default TTL `QUOTE_TTL_MS = 15000` if `expires_at` is missing.
- Submit without a live quote: “Quote first. Nothing was signed.”
- Expired: “Quote expired. Request a new quote. Nothing was signed.”
- Unlocked phrase required before sign.
- Approval loop: sign allowance → `broadcastRaw` → `buildSwap` again → swap tx.
- `CLIENT_SHIPPED` must not match `helius|jupiter|lite-api.jup|mainnet.helius|trongrid|sunswap|alchemy`.

### 4.3 What this does not prove

A live 200 from `https://tkrwallet.scratchpost.ai/api/wallet/swap/quote` is
extra evidence only. This host did not POST a production swap. Send remains
unsigned-calldata-not-published. Cross-chain “bridge” is explicitly refused
in the UI (`fromSel.chainId !== toSel.chainId`).
